# patrol-jev 자세히

[README 로 돌아가기](../README.md)

## 어떻게 도는가

네 걸음입니다.

1. **사진 → 글.** 생성 모델이 사진에 보이는 것과 주소판 글자를 적습니다. 판단은 하지 않습니다.
   판정에 넘길 영어 한 줄과 화면에 보일 한국어 한 줄을 같이 받습니다.
   사진에 찍힌 날짜·시각 글자도 그대로 옮겨 적습니다.
2. **글 → 판정.** [Jev](https://docs.typesafe.ai)가 네 갈래 중 하나로 가릅니다.
   확률이 문턱 아래면 정하지 않고 비워 둡니다.
3. **주소 → 대조.** 읽은 주소를 본인 동의 실제 도로명과 맞춰 봅니다. 그 동에 없는 도로명이면
   한두 자 차이로 짚이는 도로 하나를 찾아 고치고, 갈리면 고치지 않습니다. 모델에게 다시 묻지 않습니다.
4. **판정 → 글.** 자리별로 묶고 문장을 만드는 일은 코드가 합니다.

갈래는 넷뿐입니다. **순찰사항 · 계절특수(풍수해) · 위험시설물 · 모르겠음.**

## 자리를 어떻게 나누나

차례가 곧 동선입니다. 그래서 **줄 세우는 일이 묶는 일의 절반**입니다.

**찍힌 시각을 아는 사진은 그 시각으로 줄 세우고, 모르는 사진은 맨 뒤에 따로 둡니다.** 모르는
사진을 아는 사진 사이에 꽂지 않고, 묶을 때도 서로 섞지 않습니다. 파일 수정 시각이나 이름으로
메워 줄 세우면 조용히 틀린 차례를 만듭니다(메신저로 받은 사진은 첫 장 이름에만 번호가 없어
이름순에서 맨 뒤로 갑니다). 어느 쪽으로 줄 세웠는지는 화면에 적히고, 시각을 모르는 사진은
점선 테두리입니다.

줄을 세우고 나면 끊는 자리는 넷뿐이고, 센 것부터 이 차례입니다.

1. **시각.** 앞 장과 5분 넘게 벌어지면 무엇보다 먼저 끊습니다. 걸어서 다음 자리까지 가는 데
   걸리는 시간이 자리를 나눕니다. 같은 주소판 앞에서 찍혔어도 두 시간 벌어졌으면 다른 일입니다.
2. **주소판.** 주소판이 자리의 경계입니다. 자리에 닿자마자 주소판을 찍는 사람이 있고 일을
   끝내고 찍는 사람이 있어서, **어느 쪽인지는 그날 사진이 알려 줍니다**. 찍힌 시각을 알면
   주소판마다 앞 장과 뒷 장의 간격을 견줍니다. 주소판 뒤가 분명히 더 벌어졌으면 일을 끝내고
   찍는 사람, 앞이 더 벌어졌으면 닿자마자 찍는 사람입니다(한 자리 안은 분 단위, 자리 사이는
   걸어가는 시간). 시각이 없으면 첫 주소판 앞과 마지막 주소판 뒤의 장수로 봅니다. 한쪽으로
   못 박아 두면 다른 버릇을 가진 사람에게는 자리가 통째로 한 장씩 밀리고, 애써 읽은 주소가
   옆자리 것이 됩니다.
3. **갈래.** 이어 오던 자리가 한 갈래를 분명히 정했는데 이 장이 다른 갈래를 분명히 말하면
   끊습니다. 청소 자리를 끝내고 걸어가다 그늘막을 한 장 찍으면, 앞 장과 2분 안이라도 그
   자리에 붙이지 않습니다. 「모르겠음」과 주소판은 어느 쪽에도 표를 내지 않으니 치운 뒤
   사진이 「모르겠음」으로 나와도 자리는 안 갈라집니다.
4. **같은자리 확률.** 주소판이 하나도 없는 구간에서만 씁니다. 주소판이 그은 선을 확률로 다시
   긋지 않습니다. 그 확률은 캡션만 보고 내는 값이라 치우기 전과 치운 뒤가 달라 보이면
   같은 자리인데도 낮게 나옵니다(실물 18장 중앙값 0.20).

**애매하면 나눕니다.** 나눠 둔 둘을 합치는 것은 한 번이면 되지만, 잘못 합친 하나를 나누는 것은
번거롭습니다. 어느 쪽이든 현장 탭에서 「위와 합치기」·「여기서 나누기」로 고칩니다.

**시각은 코드가 읽습니다.** 메신저로 오간 사진은 EXIF 가 벗겨져 있어 찍힌 시각이 화면 글자에만
남습니다. 그 글자를 파싱해 자리를 묶는 데 씁니다.

**아이폰 사진(HEIC)도 그대로 올리세요.** 브라우저는 HEIC 를 못 엽니다(「The source image could
not be decoded.」가 그 소리입니다). 그래서 HEIC 일 때만 변환 도구를 그 자리에서 받아
**브라우저 안에서** 변환합니다. 처음 한 번 잠깐 걸리고, 원본은 여전히 나가지 않습니다.
한 장이 안 열려도 나머지는 그대로 갑니다. 어느 파일이 안 열렸는지 이름으로 알려 줍니다.

**같은 판정이면 늘 같은 글입니다.** 1번은 생성 모델이라 회차마다 문장이 조금 달라집니다.
2번은 같은 글을 주면 같은 답이 나왔습니다(30장을 두 번 재서 갈래는 모두 같았고 확률 차이는 0.05 안).
3번과 4번은 코드라 흔들릴 자리가 없습니다.

## 안 하는 것

일부러 뺐습니다. 도구가 무거워지면 아무도 안 씁니다.

| 안 하는 것 | 왜 |
|---|---|
| 양식 편집기 | 한글 파일은 내려받는 데까지입니다. 고치는 일은 한글에서 합니다. |
| 위험성 등급 판단 | 등급은 담당자가 매길 일입니다. |
| 폐기물 종류 분류 | 일지에 안 들어갑니다. |
| 로그인 · 데이터베이스 · 지도 · 결재 | 하루 한 번 쓰는 도구에 필요 없습니다. |
| 사진 서버 보관 | 줄인 사본을 모델에 보내고 그걸로 끝입니다. 저장하지 않습니다. |

## 자리가 갈라졌을 때

- **사진 옮기기.** 자리 칸의 「사진 옮기기」를 누르고 옮길 장을 고른 뒤, 옮겨 넣을 자리의 「N번 여기로」를 누르면 그 장이
  그 자리로 갑니다. 「새 자리로」는 고른 장만 따로 뗍니다. 「위와 합치기」는 이웃끼리만 되는데, 시각이 잘못 읽혀 멀리 떨어진
  장은 이 길로 제자리에 넣습니다.
- 사진에 찍힌 글자의 **연도만** 다르게 읽힌 장(「2025년 9월 23일」처럼)은 그날 날짜로 맞춥니다. 월·일까지 다르면 손대지 않습니다.
- 사진 칸에서 빼는 주소판은 묶기보다 좁게 봅니다. 벽의 작은 번호판 글자만 읽힌 작업 사진(치운 뒤 출입구 같은)은 사진 칸에
  그대로 실립니다. 주소판일 확률이 문턱을 넘는 장만 뺍니다.
- 시각이 아예 없는 장은 **올라온 차례의 옆 장 시각**을 빌려 그 자리에 둡니다(섬네일에 「옆 장」). 시각을 아는 장이 과반일 때만
  그렇게 하고, 손댄 것은 올린 직후 한 줄로 알립니다.

## 한글 파일로 받기

보고서 탭에서 **한글 파일(.hwpx)** 을 누르면 화면의 글을 그대로 담은 기본 양식이 내려옵니다.

- 1쪽은 굵은 틀 하나가 통째로 두릅니다. 안에 제목, 순찰 개요(일시·순찰자·지역·처리 개소), 란마다
  머리띠(「□ 순찰사항」 · 개소 수)가 붙은 본문(순찰사항·계절특수·위험시설물·주민소통·특이사항)이 들어가고,
  본문 칸은 한 쪽이 꽉 차게 나눕니다. 글이 넘치면 칸이 자라 다음 쪽으로 이어집니다.
  상표나 도구 이름은 넣지 않습니다. 결재에 올라가는 종이입니다.
- 2쪽부터는 현장 사진입니다. **순찰사항은 정비 전·후 두 장**, 계절특수·위험시설물·주민소통은 전·후가 없는
  날이 많으니 **「현장 확인」으로 한두 장**입니다. 주소판 사진은 빼고, 순찰사항은 판정이 「전」「후」라고 본
  장을 각각 둡니다. 판정이 없으면(직접 적는 길) 첫 장이 전, 마지막 장이 후이고, 한 장뿐이면 후에 둡니다.
- **글이 원천입니다.** 화면에서 글을 고치면 파일에도 고친 대로 들어갑니다. 「※ 특이사항:」 뒤에
  적은 말은 특이사항 칸으로, 「□ 주민소통」 을 새로 적으면 그 칸으로 갑니다.
- 파일은 **이 브라우저 안에서** 만듭니다. 사진도 글도 서버로 가지 않습니다.
- 순찰자 칸은 `patrol.config.json` 의 `officer` 로 채웁니다. 비워 두면 빈 칸입니다. 지어내지 않습니다.
- 안 될 때는 **까닭이 그대로 뜹니다.** 인터넷 끊김, 서버 재시작 중, 키 틀림, 잔액(크레딧) 소진, 분당 한도, 모델 서버 붐빔,
  사진 읽기 서버 연결 실패가 각각 다른 말로 나옵니다. 올린 사진은 그대로 있으니 안내대로 하고 다시 누르면 됩니다.
  읽은 주소판의 도로명이 고른 「우리 동」에 없는 장이 더 많으면 **사진과 우리 동을 맞춰 달라**고 알립니다(주소는 고치지 않습니다).

기본 양식이 본인 동 양식과 다르면 글을 복사해 붙이세요. 글이 먼저이고 파일은 그 글을 옮겨 적은 것입니다.

## 기간 보고서로 모으기 · 주간 일지

일지는 하루치이고 결과 보고는 한 주·한 달치입니다. 사이에 있는 일은 **세는 일뿐**이라 코드가 합니다.
「지난 기록」을 열면 달력 아래에 **기간 보고서 · 주간 일지**가 있습니다.

- **주 · 달 · 직접** 가운데 고르면 그 기간에 이 기기에서 만든 일지를 모아 바로 셉니다. 결과 보고서는 **주 단위**로
  내는 것이 기본이고(「9월 3주차」, 그 주 월요일 날짜로 센 주차), 달을 고르면 그 달의 주들이 그대로 합쳐집니다.
- **순위·등급·평가 칸은 없습니다.** 숫자와 자리만 있습니다. 어디가 잘했고 미흡한지는 받는 쪽이 자기 기준으로 봅니다.
- **글 복사**는 일지와 같은 줄머리(□ ○ -)의 글입니다. 본인 양식에 붙이면 됩니다.
- **결과 보고서(.hwpx)** 는 기본 양식입니다. 한 파일에 다 담기고 쪽수 제한은 없습니다.
  1. 1쪽: 제목 · 기간 · 순찰 일수 · 순찰자 · 처리 개소, 「□ 추진 실적」(란별 개소와 총계 · 기능부서 정비요청 · 동 자체정비),
     「□ 일자별 실적」, 「□ 위험시설물 점검 내역」, (있으면) 주민소통 · 특이사항. 핵심만.
  2. 「1. 기능부서 정비요청 및 자체정비 추진 실적」: 결과 보고 양식의 항목표(구분 × 내용) **전부**. 사진으로 아는 줄만
     숫자가 들어가고(순찰사항 → 청소 · 기타, 계절특수 → 치수방재 · 기타, 그늘막 → 공공시설물 · 기타, 위험시설물 → 재난위험시설
     순찰활동 또는 정비요청) **나머지는 빈 칸으로 보입니다.** 0 은 「없었다」, 빈 칸은 「이 도구로는 모른다」입니다.
  3. 「2. 기능부서 정비요청 세부내역」: 일지의 말에 **통보 · 신고 · 요청**이 적힌 자리. 요청부서와 문서번호는 담당자가 적습니다.
  4. 「3. 동 자체 정비실적 세부내역 · 현장 사진」: 란별로 묶고 그 안에서 날짜 차례. 자리마다 표 하나(연번 · 날짜 · 주소 · 말).
  사진은 **자리마다 · 순찰사항만 · 없음** 가운데 고릅니다. 한 달치는 자리가 많으니 순찰사항만이 보통 알맞습니다.
- **주간 일지**는 「주」를 골랐을 때 나옵니다. 그 주의 하루치를 날짜 차례로 이어 붙인 것으로, 날마다 1쪽 글 + 1쪽 사진(표 셋,
  여섯 장)이고 띠에 「9월 3주차 · 1/5」 처럼 몇째 날인지 적힙니다. 기재가 없는 날은 빈 셋을 넣지 않습니다.
- 모델을 부르지 않고 서버로 아무것도 안 갑니다. 이 기기에 남은 것만 셉니다.

이 기능이 생기기 전의 기록에는 자리 목록이 없어 그런 날은 순찰 일수에만 들고 개소는 「-」 로 적힙니다.

잘못 만든 날은 달력에서 그 날을 열고 **「이 날 지우기」**를 두 번 누르면 글·자리 목록·사진 사본이 이 기기에서 지워집니다.

**폰을 바꾸면** 「기록 내보내기(zip)」로 받아 새 폰에서 「들여오기」 하면 이어집니다. zip 에는 일지 글·자리 목록과
사진의 작은 사본이 듭니다. 같은 날짜는 들여온 것이 이깁니다.

## 왜 모델이 둘인가

Jev 는 이미지를 받지 않습니다(텍스트·JSON 만). 그래서 한 번은 눈이 필요합니다.
대신 갈래를 나누는 일은 Jev 가 합니다. 생성 모델에게 분류까지 맡기지 않는 까닭은 셋입니다.

- **분포가 나옵니다.** 고른 값 하나가 아니라 네 갈래 전부의 확률이 돌아오고, 화면에 그대로 보입니다.
- **못 정했다고 말합니다.** 문턱 아래면 「모르겠음」으로 둡니다. 그럴듯한 오답보다 빈칸이 낫습니다.
- **출력이 무료입니다.** 입력만 과금입니다([단가](https://docs.typesafe.ai/models)).

화면의 색 규칙은 하나입니다. **무지개빛은 Jev 가 낸 값, 회색은 생성 모델과 사람이 적은 값.**

## 모델 없이 쓰기 (직접 적어서)

화면 위에서 길을 고릅니다. **「직접 적어서」로 두면 모델을 한 번도 부르지 않습니다.**
사진은 브라우저에서 줄이기만 하고 서버로 보내지 않습니다. 비용이 0 이고, 키도 필요 없습니다.

이 길이 필요한 자리는 셋입니다.

- 맛보기 한도를 다 쓴 사람. 그 자리에서 이어 갑니다(자동으로 넘어갑니다).
- 키를 아직 안 받은 사람. 받자마자 돌려 볼 수 있습니다.
- **사진을 기관 밖으로 못 보내는 곳.** 내부망 규정이 있으면 이 길이 유일합니다.

사람이 채우는 것은 **자리와 말 둘뿐**입니다. 나머지는 자동일 때와 같은 코드가 합니다.

| 하는 일 | 누가 |
|---|---|
| 사진을 자리별로 묶기 | 코드 (찍힌 시각. 없으면 장수) |
| 찍힌 시각 읽기 | 코드 (EXIF) |
| 주소 | 사람 (고른 동의 도로명으로 자동완성) |
| 일지에 적을 말 | 사람 (자주 쓰는 말은 눌러서) |
| 갈래 | 말을 고르면 따라옵니다 |
| 일지 문장·달력·학습 | 코드 |

묶기는 **찍힌 시각이 있으면 시각으로** 합니다. 한 자리에서 두 장 찍는 데는 몇 분이 안 걸리고
걸어서 다음 자리까지 가는 데는 걸리기 때문입니다. 시각을 아는 장이 절반이 안 되면 그때
장수로 끊습니다(기본 세 장 = 치우기 전·치운 뒤·주소판). 무엇으로 묶었는지는 화면에 적힙니다.
어느 쪽이든 자리는 눌러서 합치고 나눌 수 있습니다.

**말이 갈래를 끌고 옵니다.** 「폐기물 처리 및 수거」를 고르면 순찰사항, 「배수구 주변 폐기물
처리 및 수거」면 계절특수, 「현장 확인」이면 위험시설물입니다. 그래야 사람이 채울 칸이 둘로
끝납니다. 따라온 갈래는 칸에 그대로 보이니 틀렸으면 그 자리에서 고칩니다.
새로 친 말은 그때 보이던 갈래와 함께 기억되어 다음 회차 목록에 올라옵니다.

이 화면에는 **무지개빛이 하나도 없습니다.** Jev 가 낸 값이 없기 때문입니다. 확률도 막대도
그리지 않습니다. 색이 곧 출처라는 규칙이 여기서도 그대로입니다.

사진에 찍힌 주소판 글자와 워터마크 시각은 **읽지 않습니다.** 그건 눈이 있어야 하는 일이라
모델 없이는 못 합니다. 코드가 사진에서 가져올 수 있는 것은 EXIF 시각 하나뿐이고, 그건
메신저로 오간 사진에서는 벗겨져 있습니다. 못 읽은 자리는 비워 둡니다. 지어내지 않습니다.

## 키

둘 다 본인 것으로 발급해 본인 컴퓨터에서 씁니다.

| 환경변수 | 어디에 쓰나 | 발급 |
|---|---|---|
| `OPENAI_API_KEY` | 사진 → 글 | https://platform.openai.com |
| `TYPESAFE_API_KEY` | 글 → 판정 | https://console.typesafe.ai |

`TYPESAFE_API_KEY` 가 없어도 돌아갑니다. 갈래가 전부 「모르겠음」이 되고 사람이 정하게 됩니다.
**둘 다 없어도 돌아갑니다**. 위의 「직접 적어서」로 열립니다. 사진까지 읽히려면
`OPENAI_API_KEY` 가 있어야 합니다.

사진을 모델에 보낼 때 국외로 나갑니다. 내부망 규정이 있는 곳에서는 그 규정을 먼저 확인하세요.

## 도로명 대조 (권장)

주소판은 생성 모델이 곧잘 헛읽습니다. 실물 30장으로 재 보니 열 곳 중 넷이 틀렸습니다.
「○○로13길」을 「◇◇로13길」로 읽는 식입니다. 그 동에 그런 도로가 없으니 코드가 알아봅니다.

1. [도로명주소 누리집](https://business.juso.go.kr)에서 「**도로명주소 한글**」(TXT)을 내려받습니다.
2. 압축을 풀어 `road/` 아래에 둡니다.
3. `npm run roads:build`
4. 화면 위 「**우리 동**」에서 본인 동을 고릅니다. 한 번 고르면 그 브라우저는 기억합니다.

같은 30장에서 **주소 아홉 곳이 전부 맞았습니다**(대조를 끄면 다섯 곳). 목록에 없는 글자를
읽었을 때만 손을 대고, 비슷한 도로가 둘 이상이면 고치지 않습니다. 건물번호가 그 도로에 없으면
고치지 않고 화면에 표시만 합니다. 번호는 짐작할 것이 못 됩니다.

내려받은 원본과 만들어진 색인은 레포에 들어가지 않습니다(`road/` 는 `.gitignore`).

## 본인 동에 맞추기

고칠 파일은 `patrol.config.json` 한 장뿐입니다.

```jsonc
{
  "dong": "○○동",              // 일지 머리글에 찍힙니다
  "unit": "환경순찰",
  "officer": "",                // 한글 파일의 순찰자 칸. 비우면 빈 칸입니다
  "threads": "",                // 발치 「PJ(patrol-jev)」 가 가리킬 주소. 비우면 이 레포로 갑니다
  "roads": [],                  // 자주 나오는 도로명. 비워 두어도 됩니다
  "seasonalSpots": [],          // 그늘막처럼 자리가 고정인 점검 지점
  "thresholds": {
    "lane": 0.8,                // 이 아래면 갈래를 안 정하고 사람에게 넘깁니다
    "sameLocation": 0.5,
    "addressPlate": 0.7,
    "sameMinutes": 2,           // 앞 장과 2분 안이면 같은 자리로 잇습니다 (0 = 안 씀)
    "splitMinutes": 5,          // 이 분 넘게 벌어지면 무조건 다른 자리 (주소판보다 셉니다)
    "workShot": 0.8             // 전·후 작업 사진이 이만큼 분명하면 글자가 읽혀도 주소판으로 안 봅니다
  },
  "manual": {
    "groupSize": 3              // 직접 적을 때, 찍힌 시각이 없으면 몇 장씩 한 자리로 끊을지
  }
}
```

`roads` 는 화이트리스트가 아니라 참고 목록입니다. 도로명 색인을 만들고 동을 골랐으면 그 동의
도로명이 자동으로 참고 목록이 되니 비워 두어도 됩니다. 색인 없이 쓸 때만 손으로 몇 개 적어
두세요. 그것만으로도 30장 기준 주소판 판독이 6/10 에서 9/10 으로 올랐습니다.

`manual.groupSize` 는 직접 적을 때만 씁니다. 찍힌 시각이 살아 있으면 이 값 대신
`sameMinutes` 로 묶습니다. 한 자리에서 몇 장을 찍는지는 동마다 다르니 본인 습관에 맞추세요.

`sameMinutes` 는 사진을 어떻게 묶을지를 정합니다. 한 자리에서 전후 두 장을 찍는 데는 몇 분이
안 걸리고 걸어서 다음 자리까지 가는 데는 걸립니다. 그래서 찍힌 시각이 붙어 있으면 같은 자리로
잇습니다. 문턱값은 본인 동 사진으로 재 보고 바꾸세요. 기본값은 출발점일 뿐입니다.

일지 문구는 화면에서 고칩니다. 보고서의 **수정**을 누르면 글을 고칠 수 있고, 고친 말은 다음
회차에도 쓰입니다. **처음 문구로**를 누르면 되돌아갑니다.

## 판단을 검토하려면

질문의 문장과 문턱값은 `src/core/judgment.ts` 한 파일에 모아 두었습니다. 코드를 뒤질 필요 없이
그 파일만 읽으면 이 도구가 무엇을 어떻게 묻는지 다 보입니다.

질문은 영어로 썼습니다. Jev 문서가 영어에서 정확도가 가장 좋다고 적고 있어서입니다.
사진에서 읽은 한글은 번역하지 않고 원문 그대로 넘깁니다. 주소는 옮기는 순간 틀립니다.

고친 뒤에는 검사를 돌리세요.

```bash
npm run dev
npm run check          # 판정 10건. 진짜 API 를 부릅니다(판정 출력은 무료)

npm run check:time     # 찍힌 시각 읽기
npm run check:roads    # 주소를 도로명과 대조·교정하는 규칙
npm run check:report   # 묶기와 일지 문장
npm run check:manual   # 모델 없이 도는 길
```

아래 넷은 API 도 사진도 인터넷도 없이 돕니다. 노드 22 이상이 필요합니다. 검사가 `src/core` 의
TypeScript 를 그대로 읽기 때문입니다. 검사용 사본을 두면 언젠가 갈라집니다.

## 지난 기록과 학습

둘 다 이 컴퓨터에만 쌓입니다. 보내는 코드가 없습니다.

- **달력.** 일지를 한 번 만들면 그날 날짜가 남습니다. 지난 날짜를 누르면 그날 일지 글을 다시
  꺼내 복사할 수 있습니다. 회차가 끝난 뒤 고친 것(합치기·나누기·갈래·말·글)은 같은 날짜에 덮입니다.
  **일지에 실린 사진의 작은 사본**(정비 전·후, 긴 변 720px)도 같은 날짜로 이 브라우저(IndexedDB)에 남습니다.
  기간 보고서의 사진 표가 여기서 나옵니다. 원본은 남기지 않고, 어디로도 보내지 않습니다. 한 해가 지난 것은 지웁니다.
- **고친 것 기억.** 주소가 있는 자리에서 갈래를 고치면 **그 주소에** 기억합니다. 다음에 같은
  자리가 나오면 기계가 뭐라고 했든 지난번 답으로 적힙니다. 옹벽에 금이 가 있고 도로가 파손된
  자리라 기계는 늘 「위험시설물」로 보지만, 그 자리에서 담당자가 하는 일은 청소이고 일지에
  적는 란도 순찰사항인 경우가 있습니다. 사진에 안 보이는 사정이라 기계는 알 수 없습니다.
  대신 **덮었다는 것을 숨기지 않습니다**. 카드에 「지난번 고친 대로 · 기계는 위험시설물」처럼
  같이 적힙니다. 그 자리에 정말 다른 일이 생긴 날에는 도로 고치면 되고, 기억도 그 값으로 바뀝니다.
  온 동네에 퍼지는 규칙이 아니라 **그 한 자리의 사정**입니다.

## 개인정보

- 다루는 것은 청소 전후와 현장 사진입니다. 사람이 찍히면 쓰지 마세요.
- 원본 사진은 브라우저 밖으로 나가지 않습니다. 긴 변을 줄인 사본만 모델로 갑니다. 그 사본에는
  찍힌 시각·자리 같은 기록(EXIF)이 없습니다. 좌표는 읽지 않습니다.
- 사용 기록(장수·걸린 시간·고친 횟수)과 지난 일지·사진 사본은 이 컴퓨터에만 쌓입니다. 어디로도 보내지
  않습니다. 끄려면 `patrol.config.json` 의 `log.mode` 를 `"off"` 로 두세요. 그러면 달력도 기간 보고서도 비어 있습니다.

## 속도

화면에 찍히는 숫자는 그 회차에 실제로 잰 값입니다. 미리 적어 둔 값이 아닙니다.

아래는 한 동의 실제 순찰 사진 30장으로 잰 값입니다(긴 변 1024 · 장당 한 번씩 · 동시성 6과 8).
사진과 회선이 다르면 달라집니다.

| 단계 | 30장 벽시계 | 장당 중앙값 |
|---|---|---|
| 사진 → 글 | 22.9초 | 4,170ms |
| 글 → 판정 (Jev) | 1.6초 | 258ms |

30장 한 회차에 25초 안팎입니다. 느린 쪽은 언제나 사진을 읽는 단계이고, 갈래를 가르는 쪽은
그 10분의 1도 안 걸립니다.
